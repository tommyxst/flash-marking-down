# 验收规格 v1.0

更新于 2026-11-24，与 [开发规格 v1.0](../../SPECIFICATION.md) 和 [实施计划 v1.0](implementation-plan.md) 配套。本版聚焦个人日常可用的核心闭环，将原 40 条重型验收用例收敛为 **12 条务实核心用例（AT-01 至 AT-12）+ 1 条端到端主流程（E2E-Core）**。

所有自动化和手工写入测试均在可丢弃的临时工作区和隔离 OpenViking 前缀下执行，绝不写入真实生产知识库或共享团队记忆。

## 1. 核心验收用例（AT-01 至 AT-12）

| ID / 阶段 | 验证场景 | 预期可观察结果 |
|---|---|---|
| **AT-01 / R1** | **工作区、统一配置与务实文件兼容**：选目录打开工作区，将应用保持运行状态在外部重命名父目录或拷贝备份工作区到新路径重开；并在含 Junction/软链接的目录中检索。 | 配置读写 `settings.json` 正常；重启恢复工作区不因 NTFS 索引号变化报错；不锁死父目录，正常识别常规软链接/云盘文件；自动排除 `.flash-marking-down` 且拒绝工作区越界读写。 |
| **AT-02 / R1** | **模型与 OpenViking 一屏配置 + 测试连接**：在设置弹窗填写模型地址/名称/API Key 并一次保存，点「测试连接」；再配置本机 OpenViking 地址与密钥并测试连接。 | 密钥安全写入 Windows 凭据管理器（不进工作区与日志）；测试连接清晰区分连通成功（含身份/模型确认）、认证失败与网络不可达。 |
| **AT-03 / R1** | **快捷窗秒记、每日文件追加与草稿逃生**：全局热键唤出快捷窗，用中文输入法组词并按 `Enter`/`Ctrl+Enter`/`Esc`；连续保存两条笔记；模拟目录只读触发保存/草稿失败。 | 组词不误触发保存或关窗；两条笔记按时间戳块顺序追加到当日 `YYYY-MM-DD.md`，不覆盖当天已有人工内容；失败时编辑器**不锁只读**，可复制正文或选择忽略草稿强制关闭/退出托盘。 |
| **AT-04 / R1** | **轻快待办勾选（含手工任务）**：在映射的 Markdown 任务清单中同时包含应用提取任务与手工 `- [ ]` 任务；在主屏连续勾选/取消勾选；在外部编辑器修改该文件后再勾选。 | 两种任务均可直接点击勾选并实时写回 `[ ]`/`[x]`；不往 Wiki 变更列表灌水；若目标行已被外部修改，提示冲突并刷新而不静默覆盖外部改动。 |
| **AT-05 / R2** | **保存后即时后台自动整合与失败容错**：启用模型后通过快捷窗保存一条含讨论、决定与待办的笔记；再断网或关闭模型保存第二条。 | 第一条保存瞬间关窗，数秒后主屏中栏内联区自动出现摘要、决定与待办（缺失负责人/日期保持空缺）；第二条照常秒存，仅安静显示未整合/失败状态并提供「重试」按钮，无弹窗打扰。 |
| **AT-06 / R2** | **一屏三栏主工作台闭环**。在主屏顶部 `Ctrl+K` 搜索，切换左栏「记录 / Wiki / 待办」，在 Wiki 按目录浏览并按路径筛选，在中栏查看原文，右栏发起多轮对话并切换历史会话。 | 左栏在 230px 窄栏横向容纳三个页签。Wiki 列表排除快记目录、历史快记和待办清单。中栏本地图片正常渲染，脚本与未授权外链图片被阻断。主流程隐藏内部标识，刷新后保留对话历史。 |
| **AT-07 / R2** | **Git 冲突式分歧发现与三选一决策**：连续记录两条观点相反的笔记触发冲突检测（或手动发起冲突对比），打开右上角抽屉查看 Git 风格 Diff，分别验证 `Keep Current`、`Accept Incoming`、`Keep Both`。 | 抽屉清晰展示双方主张、来源与日期 Diff；选择任一决策后状态正确更新且徽章计数减少；选择 `Keep Both` 后后续对话召回同时提醒双方观点；单条冲突记录损坏不导致问答瘫痪。 |
| **AT-08 / R2** | **Wiki 阅读、维护与变更审阅**。新建嵌套 Wiki 页，保存并搜索正文，切换目标映射。从中栏打开关联建议的 Diff，采纳、拒绝或撤销，再从抽屉「工作台查看」返回。采纳前也用外部编辑器修改目标页尝试冲突路径。 | 新建后直接编辑，重开默认预览。保存、采纳、撤销后搜索反映当前正文。外部改动触发重新比较，撤销保留后续人工编辑。返回时抽屉收起，对应 Wiki 页在中栏打开。 |
| **AT-09 / R3** | **OpenViking 双路同步与离线补推**：启用本机 OpenViking，保存一条新笔记并验证后台双路同步；停止 OV 服务后再保存一条，恢复服务后点击补推/等待重试。 | 正常时每日文件自动写入 `viking://resources/flash-marking-down/<workspace>/daily/YYYY-MM-DD.md`，整理要点通过 Session Commit 触发记忆抽取；OV 离线时不阻塞本地保存，恢复后补推成功并更新状态徽章。 |
| **AT-10 / R3** | **本地 + OpenViking 双源混合对话召回**：在右栏询问只存在于 OV 记忆中的旧背景以及刚记在本地的新笔记；再断开 OV 重问。 | 正常时流式回答同时融合本地与 OV 命中，来源清晰标注 `[本地]` / `[OV记忆]` / `[OV资源]` 且点击引用可预览原文；允许自由 `Ctrl+C` 复制并支持一键「复制（含引用出处）」；OV 离线时自动降级纯本地回答并温和标注。 |
| **AT-11 / R1–R3** | **安全与可访问性边界**：尝试路径穿越（`../`）、含 `<script>` 与外链跟踪图的 Markdown、125%/150% Windows 缩放与纯键盘核心操作。 | 越界路径被拒；脚本不执行、外链图不自动加载；密钥不出现在数据库、日志或界面明文中；125%/150% 缩放下三栏与抽屉布局不遮挡、键盘焦点清晰。 |
| **AT-12 / R1–R3** | **性能基线复核**：实测托盘常驻隐藏复用下的快捷窗热唤出（30 次）、单条保存写盘（30 次）及 5,000 篇合成文档离线检索（20 条含单/双汉字查询）。 | 常规热唤出 p95 ≤ 300 ms；单条本地保存 p95 ≤ 200 ms；5,000 篇增量重建与混合搜索 p95 ≤ 2 s；记录常驻内存与 CPU 供实测校准。 |

## 2. 端到端主链路（E2E-Core）

> **场景：真实工作一天的完整闭环**
> 1. 后台托盘常驻，按全局快捷键唤出快捷窗，用中文输入法随手记下刚开完会的讨论结论与待办，`Ctrl+Enter` 秒存回到原工作；
> 2. 后台自动将记录追加到当日 `YYYY-MM-DD.md`，自动完成模型整理并将原文写入 OpenViking 资源目录、提交要点抽取长期记忆；
> 3. 随后再记一条与先前结论存在分歧的新想法，右上角亮起「冲突/变更 (1)」提示；
> 4. 打开主工作台：在左栏看到今日记录与自动提取的待办，直接勾掉一项已完成待办；点开右上角冲突抽屉，像 Git 解冲突一样看 Diff 并选定采纳新方案（或保留双方条件）；
> 5. 在右侧对话面板提问“最近关于这个方案怎么定的、还有什么待办？”，获得结合本地笔记与 OpenViking 历史记忆的流式回答，点击引用验证原文，自由复制结论投入后续工作。
